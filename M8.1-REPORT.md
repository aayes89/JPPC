# JPPC — M8.1: Xenon SPR, Time Base y Decrementer

## Objetivo

Corregir y fijar mediante pruebas la semántica de registros de tiempo visibles por software PPC/Xenon. Esta entrega no pretende completar todos los SPR específicos de Xenon ni la MMU.

## Hallazgos y correcciones

1. **TBL incorrecto en `mfspr`:** `CPU.getSPR()` devolvía los 64 bits completos para SPR 268/284. Ahora devuelve los 32 bits inferiores.
2. **TBU:** SPR 269/285 devuelve explícitamente los 32 bits superiores.
3. **Time Base carry:** se prueba el paso `0x00000000FFFFFFFF` → `0x0000000100000000`.
4. **DEC:** se eliminó el clamp que convertía cualquier valor negativo escrito al decrementer en cero. El registro conserva su patrón de 32 bits.
5. **DEC underflow:** `tick()` decrementa con aritmética de 32 bits y marca la excepción al cruzar de un valor no negativo a uno negativo. Llegar a cero por sí solo no genera la excepción; `checkInterrupts()` la entrega cuando `MSR[EE]` está habilitado.

## Pruebas nuevas

`pcp.TESTS.XenonTimebaseSelfTest` ejecuta instrucciones `mfspr` reales a través del decodificador de CPU y comprueba TBL/TBU (268, 269, 284, 285), propagación del carry del Time Base, transición DEC 1→0→0xFFFFFFFF y preservación de un patrón DEC con bit 31 activo.

Ejecución aislada:

```bash
java -cp out pcp.TESTS.XenonTimebaseSelfTest
```

Regresión completa:

```bash
./run.sh test
```

## Límites conocidos

- La entrega no valida todavía el comportamiento temporal exacto del Xenon bajo múltiples hilos ni la frecuencia física del Time Base. `--tb` continúa siendo un factor de avance de emulación, no una calibración de reloj real.
- No se han completado todos los SPR HID/HRMOR/LPCR, BAT ni registros de depuración Xenon.
- La ruta de excepciones y el mapeo completo de vectores requieren una auditoría separada.
- No se declara compatibilidad 1BL ni arranque de dashboard.
