# JPPC M8.3 — DSI/ISI exception entry foundation

## Objetivo

Unificar la entrada de excepciones de almacenamiento/instrucción entre la MMU y la CPU, y conservar el estado arquitectónico mínimo necesario para diagnosticar fallos de traducción.

## Cambios

- `CPU.raiseStorageException(...)` centraliza la entrada DSI/ISI usando la ruta interna `takeException(...)`.
- DSI guarda la dirección efectiva que falló en DAR.
- DSI establece DSISR bit 25 para identificar una operación de escritura; las lecturas no activan ese bit.
- ISI utiliza el vector `0x400` y conserva SRR0/SRR1 mediante la ruta de CPU.
- MMU deja de llamar a un `ExceptionHandler` que solo implementaba realmente la excepción de programa; ahora delega DSI/ISI directamente en la CPU.
- `ExceptionHandler` enruta DSI/ISI a la misma entrada de CPU para evitar una ruta paralela.
- Se añade `XenonExceptionSelfTest`, que verifica DAR, DSISR, SRR0 y limpieza de bits MSR para DSI/ISI.

## Validación ejecutada

- `ant clean jar`: BUILD SUCCESSFUL.
- `./run.sh test`: exit code 0.
- 30 comprobaciones OK, 0 FALLA.
- Regresión CPU PPC32, PPC64/FP, VMX, LK, XeLL, Xenos, SATA/ATAPI y NAND sintética.
- Las pruebas NAND son sintéticas; no se usó un dump real.

## Limitaciones explícitas

M8.3 no completa la MMU Xenon/PPC64 ni declara listo el arranque de 1BL.

- El TLB continúa siendo una tabla simplificada de entradas VPN/PPN/VSID; no implementa la búsqueda hash PPC completa.
- SDR1 todavía no controla una page table hash funcional.
- No se han implementado permisos PP/RW, atributos WIMG ni protección completa de páginas.
- `tlbie`, `tlbia`, `tlbsync` y coherencia de invalidación requieren semántica dedicada.
- La ruta de fallo todavía necesita integrarse con todos los accesos de memoria para garantizar que ningún call-site continúe usando una dirección física de sustitución después de una excepción.
- `rfi`/`rfid` requiere pruebas de restauración completa MSR/SRR y control de flujo; esta entrega no afirma recuperación completa.
- No se ha ejecutado 1BL ni se ha probado una cadena de arranque real.

## Próximo orden técnico

1. Propagar fallos de traducción como resultado explícito y abortar el acceso que los originó.
2. Completar DSI/ISI, SRR0/SRR1 y retorno `rfi`/`rfid` con pruebas de flujo.
3. Implementar TLB y operaciones de invalidación.
4. Implementar SDR1 y page table hash PPC.
5. Aplicar permisos y atributos de página.
6. Auditar SPR/instrucciones privilegiadas y comparar con el código de arranque disponible.
7. Ejecutar pruebas controladas con firmware de prueba antes de considerar 1BL.

No se incluyen NAND, KeyVault, CPU key, DVD key ni otros datos privados.
