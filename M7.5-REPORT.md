# JPPC — Milestone M7.5: Xenos MMIO surface/endian validation (1280x720)

## Resultado

Esta iteración valida y endurece la decodificación de la dirección de superficie primaria Xenos (`D1GRPH_PRIMARY_SURFACE_ADDRESS`, offset `0x6110`) según el modo endian configurado en el dispositivo. El callback `onSurfaceChange` ya no consume directamente el valor crudo escrito: pasa por `d(v)`, la misma conversión definida por el backend para los registros.

La prueba de ejecución determinó que **no se debe activar el modo little-endian para el `xenon.elf` actual**: hacerlo provoca `assertion "gpu_clock == 9" failed` durante `xenos_init_phase1`. La integración real mantiene el modo big-endian que permite que XeLL continúe hasta la inicialización USB. La ruta little-endian queda cubierta de forma unitaria para futuros perfiles/controladores, no activada especulativamente.

## Cambios incluidos

- `src/pcp/gpu/XenosGpu.java`: normalización endian del valor de superficie antes de notificar el cambio de dirección.
- `src/pcp/TESTS/XenosGpuSelfTest.java`: pruebas de registros, pitch y callback en modos BE y LE.
- `tests.sh`: incorpora la prueba de endianidad Xenos.
- `M7.5-REPORT.md`: este informe.
- `out/m75-fb-1280x720.png`: captura del demo MMIO 1280x720 producida por JPPC.
- `out/m75-xell-xenos.png`: captura del framebuffer Xenos de XeLL (no es UART ni ConsoleText).
- `out/m75-xell-uart.png`: diagnóstico UART separado.

## Validación ejecutada

- `ant clean jar`: BUILD SUCCESSFUL.
- `XenosGpuSelfTest`: ALL OK.
- `fb_demo_1280x720.bin`: HALT correcto; 921.600 palabras VRAM no nulas; PNG 1280x720.
- `xenon.elf`: AVPACK VGA, configuración Xenos y enumeración inicial de dos hubs USB; 786.432 palabras VRAM no nulas; ejecución limitada a 300M instrucciones (no HALT), PC `0x80008A70`.
- Regresión global: 21 comprobaciones pasan y 1 falla: `autotest CPU 32 bits (23 tests)`, que informa `W-` en el autotest. No se marca como regresión aprobada. Los demás tests de la suite pasan.

## Límites

- No se implementó un host USB EHCI/OHCI completo.
- No se falsificó el bit de estado que espera XeLL en `0xEA001307`.
- No se alcanzó el splash azul ni el menú XeLL.
- La captura XeLL demuestra actividad en la VRAM Xenos tiled; no demuestra que el logo ya se haya presentado.
- El demo 1280x720 se ejecuta con pitch lineal de 5120 bytes. La superficie Xenos tiled conserva el padding por tiles de 32x32.

## Comandos

```bash
./run.sh compile
java -Djava.awt.headless=true -cp out pcp.PCP \
  src/pcp/TESTS/fb_demo_1280x720.bin --size 1280x720 \
  --headless --max 12000000 --png out/fb_demo_1280x720.png

java -Xmx1g -cp out pcp.PCP src/pcp/TESTS/xenon.elf \
  --elf --size 1280x720 --tb 1000 --headless --max 300000000 \
  --png out/xell-xenos.png --console-png out/xell-uart.png
```
