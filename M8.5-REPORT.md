# M8.5 — TLB lookup e invalidación

## Cambios

- VPN corregido a 20 bits para direcciones efectivas de 32 bits (antes se truncaba a 16 bits).
- Lookup TLB conserva VSID, VPN y offset de página.
- `MMU.invalidateTLBEntry(EA)` invalida la entrada correspondiente al VSID del segmento y VPN de la EA.
- `tlbie` conectado a la invalidación real.
- `slbia` limpia las traducciones locales del modelo de un hilo.
- `tlbsync` queda como punto de ordenación síncrono en el modelo actual monohilo.
- Nueva prueba `XenonTlbSelfTest`: lookup, offset, invalidación individual y global.

- `./run.sh compile`: correcto.
- `./tests.sh`: 27 comprobaciones OK, 0 FALLA.
- Se ejecutaron LK y `xenon.elf` a 1024x768.
- No se ejecutó `fb_demo` ni `triangle_fixed`.

## Límites conocidos — NO declarar 1BL-ready

Este milestone valida el TLB software básico y la invalidación de entradas explícitamente insertadas por el modelo. No implementa aún la búsqueda de PTEG en hash page tables mediante SDR1, validación completa de PTE0/PTE1, permisos PP/Ks/Kp, atributos WIMG, actualización de R/C, ni todas las variantes de invalidación PPC. El código de `SDR1` sigue almacenándose en CPU, pero no dirige todavía una tabla hash real.

## Entrada 1BL

Se intentó acceder a `https://cumxtv.ddns.net/1bl.bin`. El cliente web rechazó el tipo `application/octet-stream`; el cliente de descarga del entorno falló resolviendo `cumxtv.ddns.net` (DNS). Por tanto, el binario no se obtuvo ni se ejecutó. Para cerrar la etapa con pruebas reales, se requiere que `1bl.bin` se adjunte directamente en la conversación o se proporcione un host resoluble desde el entorno.

No se incluyó NAND real ni material criptográfico en el paquete.
